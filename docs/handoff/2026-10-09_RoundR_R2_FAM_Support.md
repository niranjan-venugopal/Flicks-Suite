# Round R · R2 — The FAM support console: find anyone, suspend that really blocks, company support, billing help

**Date:** 2026-10-09 · **Migration:** `0070_fam_support_console.sql` (→ `apply-0070.sql`, run BEFORE the API deploys) · **Ships on top of:** `a86ce0e` (Round R · R1) · **Release:** API (`production`) then web (`main`) — the old web keeps working against the new API (every new field is additive; the one behaviour change the old web meets is a suspended company answering 403 `TENANT_SUSPENDED`, which it shows as a permission error until the new web lands)

Founder's brief (2026-10-07), item **1**: *"FAM should be able to help a customer who is stuck: find them, see what is wrong, unblock them, pause a company that should not be using the product, and give a company more time or free months — all of it on the record."* Founder decision: **all four toolsets** (find a person / company · a suspend that really blocks · a company support tab · billing help). R1 (items 2–7) shipped 2026-10-08; R3 (CRM closed things editable) and R4 (CRM form builder + forms on deals) follow.

## 1. What was really wrong

| Area | Before |
|---|---|
| Finding a person | The topbar search box on the console did nothing. The only way to a person was to know their company, open it and scroll the member list — and a person in two companies looked like two unrelated people. |
| A person who cannot sign in | Nothing on the console said *why* (code attempts burnt, hourly code limit hit, session gone) and nothing could lift it — support had to wait for the hour to pass or ask engineering. |
| Suspend | "Suspended" was a label on the tenant row. A suspended company's members kept signing in, kept refreshing their sessions, kept using every screen; nobody was told. Reactivate always set the company to *active* — a company on trial came back as a paying customer. |
| Company support | No way to see what a company had actually been doing (its own audit log lives in the app, Owner-only), no way to resend a stuck invite or end one member's session, nowhere to leave a note for the next support person. |
| Billing help | Extend trial added days to the *old* end date, so an expired trial stayed expired; there was no way to give a company free months short of minting a public coupon and asking them to type it in; the subscription panel showed MRR but not seats, coupon or grace. The audit-log filters and CSV button were dead. |
| Hardening found on the way | With two-factor turned on, a platform admin who never enrolled could still use the whole console (the login flagged it, nothing enforced it). An admin whose own company's trial lapsed got **402** on FAM writes (the paywall keyed on the token's role, which is *owner* of their own workspace). A short-lived TOTP challenge token was accepted as a session by the JWT strategy. `tenant_selected` was written to the sign-in history on every company switch — and silently dropped, because the enum never had that value. Several console buttons were decorative (verify queue *Reject / Snooze / Email*, cohorts *New / Announce / Edit*, feature-usage *Export*, flags *New flag*, health *Run synthetic check*). |

## 2. What changed

### Find anyone
| Change | Detail |
|---|---|
| Topbar search (`components/fam/FamSearch.tsx`) | Type two characters: **people** by email or name (with how many companies they belong to, platform / status pill) and **companies** by name, slug or GSTIN (status, active members, logo). ⌘K / Ctrl-K focuses it, Esc closes, Enter opens the first hit. The Specflicks platform tenant is never a hit. `GET fam/search?q=`. |
| Person page `/fam/users/:id` | Profile; **Companies** (role, seat status, company status, joined / invited, link to the company); **Can they sign in?** (wrong-code lockout, codes this hour / limit, authenticator lock and two-factor state for platform admins); **Live sessions** (device, company, IP, trusted / 2FA / impersonation pills, last used, expiry); **Trusted devices**; **Sign-in history** (every `auth_events` row, paged, with device / IP / details). `GET fam/users/:id`, `GET fam/users/:id/auth-events`. |
| Clear sign-in lockout | Resets the wrong-code counter on their live codes, drops the hourly code-limit keys in Redis, clears the authenticator lock. Written to their sign-in history (`account_unlocked`, by fam, actor id) and to the platform audit log with the admin's IP + browser. `POST fam/users/:id/clear-lockout`. |
| Send sign-in link | A 30-minute single-use link that skips the hourly code limit, emailed through the normal magic-link template. Sign-in history `magic_link_requested { by: 'fam', sent }`; platform audit `fam.user.sign_in_link_sent`. When the mailer refuses, the console says so (503 → "Could not send the link") instead of pretending. `POST fam/users/:id/send-sign-in-link`. |
| Sign out everywhere | Every live refresh token retired across every company, every trusted device forgotten, every open socket of theirs dropped (`seat.revoked` per company). A screen they still have open drops within 15 minutes, when its short-lived access token expires — the dialog says exactly that. `POST fam/users/:id/sign-out-everywhere`. |

### Suspend that really blocks
| Change | Detail |
|---|---|
| Suspend (`POST fam/tenants/:id/suspend`, reason required) | Saves `tenants.status_before_suspend`, sets `suspended`, retires every live session scoped to the company, emails every active **Owner** (`workspace-suspended` template, reason included), audits `tenant.suspended { reason, previousStatus, sessionsRevoked }` with IP + browser. Refused for the Specflicks tenant and for an already-suspended company. |
| It really blocks | **Login** skips memberships in suspended companies (lands in another company, or — when it was their only one — nowhere, with `suspendedTenants` naming it). **Refresh** of a session scoped to the company ends it (401, token retired). **Switch-company** into it is refused. **Every tenant route** answers `403 { code: 'TENANT_SUSPENDED', message: 'This workspace is suspended — contact support' }` from the roles guard (ranked and unranked routes alike; account routes `/auth/*`, `/me/*` stay reachable). **Sockets** refuse the company at handshake. **Public API keys** of the company answer the same 403. **Impersonating** into it is refused. |
| The web | `components/layout/SuspendedWorkspace.tsx`: instead of a page of failed calls, the person sees *"<Company> is suspended — Specflicks has suspended this workspace… your Owner has been emailed the reason"*, with **Switch to <other company>** buttons and **Sign out**. Shown when the current company is suspended **and** when every company they have is suspended (so they are never bounced into "create a company" or into a refused auto-switch). The API client reloads on `TENANT_SUSPENDED` so the screen appears even in a tab that was open at the moment of suspension. |
| Reactivate | Restores `status_before_suspend` (a trial stays a trial; `active` when nothing was recorded), clears it, emails the Owners (`workspace-reactivated`), audits `tenant.reactivated`. The Razorpay activation webhook also lifts a suspension it finds. |

### Company support tab (`/fam/tenants/:id?tab=support`)
| Change | Detail |
|---|---|
| Company activity | The company's **own** audit log (`audit_log`, exactly what its Owner sees under Reports → Audit): who, action, record, IP, before / after diff, filters (action text, record type, date range), paged, **Export CSV** (`GET fam/tenants/:id/activity`, `activity.csv`). |
| Support notes | `fam_tenant_notes`: add, pin to top, delete (soft), author + time. **Specflicks-only**: FORCE RLS with a deny-all policy and `REVOKE ALL … FROM flicks_app` — the tenant's own connection cannot read a single row (proved in the spec and live). Every note action is in the platform audit log. `GET/POST fam/tenants/:id/notes`, `PATCH/DELETE …/notes/:noteId`. |
| Member actions | **Resend invite** on an invited seat (through the new `employees/public.ts` facade → the same `resendInvite` the HR screen uses, so throttling and `employee_invitations` rows behave identically); **Sign out** a member of *this* company only (their other companies keep working); member rows now show **last sign-in** and link to the person page. `POST fam/tenants/:id/members/:membershipId/resend-invite`, `…/sign-out`. |
| Tabs | `?tab=` is honoured and kept in the URL, so search results, audit rows and emails can deep-link straight to Support / Billing. |

### Billing help (`/fam/tenants/:id?tab=billing`)
| Change | Detail |
|---|---|
| Extend trial | Counts from **max(today, current end)**: an expired trial comes back on at once (the paywall lifts immediately — billing state invalidated). Days 1–180, optional reason (platform audit only). Writes both `tenants.trial_ends_at` and `subscriptions.trial_ends_at` (and slides `current_period_end` when set, so a canceled subscription unlocks too), a `trial.extended` plan-history event, platform audit `tenant.trial.extended` with IP. Creates the subscription row when a company has none. Refused for a workspace paying through a live Razorpay subscription (its dates are decided there). |
| Give free months | Mints a **private** coupon `FAM-XXXXXXXX` (campaign `fam-support`, one use, that company only) and redeems it on the company's behalf: N calendar months on top of max(today, current end); the Owners get the usual "coupon applied" note; plan history `coupon.redeemed`; platform audit `fam.free_months_granted { code, months, reason }`. Repeatable (the uniqueness is now per *coupon*, not one coupon per company ever). Refused for a workspace already paying through Razorpay (credit it there) — the button is disabled and the API says why. Months 1–12. `POST fam/tenants/:id/free-months`. |
| Subscription panel | Adds **billable seats** (with what that would cost per month), **coupon** (code · months · campaign · when), **grace ends**, Razorpay subscription id; MRR is labelled "counts once paying" while on trial. |

### Platform audit log (`/fam/audit`)
Filters are wired: date range, **category** (impersonation / company lifecycle / person actions / member actions / support notes / coupons & free months / feature flags), action text, actor (email or name), company id; **Export CSV** with IP + user agent columns; a **From** column (IP, hover for the browser); targets link to the company or the person. The action filter understands a leading `^` (anchored) and commas (alternatives) so "Company lifecycle" never picks up `fam.tenant.note_*`. `?category=` deep links work (the feature-flags page links to its slice). The company's Audit tab gets the same filters.

### Hardening
| Change | Detail |
|---|---|
| Two-factor is enforced, not advisory | A session carries `mfa: true` only after a TOTP challenge (`/auth/totp/verify`), an enrolment confirm (`/auth/totp/confirm`) or an in-place **step-up** (`/auth/totp/step-up` — the signed-in admin proves the code and the session is re-issued with the claim). The claim is stored on the refresh token and survives rotation and company switches; a plain session never acquires it. `FamMfaGuard` (TOTP_SECRET set + platform admin + no `mfa` → **403 `TOTP_REQUIRED`**) sits on `FamController`, the FAM billing controller and the FAM feedback routes. `/auth/me` reports `totp { enforced, enrolled, satisfied }`; the console shell sends an un-enrolled admin to `/totp-setup` and shows an enrolled one whose session lacks the factor the step-up card (never a sign-in bounce). Socket handshakes refuse challenge tokens and suspended companies the same way. Without `TOTP_SECRET` (local dev) nothing changes. |
| Platform admins are never paywalled | `BillingGuard` keys on `isPlatformAdmin`, not the token's role; `FamController` is `@BillingExempt`. |
| Challenge tokens are not sessions | `JwtStrategy` rejects any token carrying a `scope` (`totp_challenge`). |
| `tenant_selected` persists | Enum value added (0070); company switches now show in a person's sign-in history. |
| Every FAM write is attributable | `logPlatform` carries the admin's IP + user agent (`clientMeta(req)`); the log and the CSV show them. |
| Dead buttons removed | Verify queue (*Reject / Snooze / Email tenant*, filter chips, export), cohorts (*New cohort / Announce / View / Edit*), feature usage (*Export CSV*), feature flags (*New flag* → the *Audit changes* link now goes to the flags slice of the audit log), system health (*Run synthetic check*). |

## 3. Migration 0070 (`apply-0070.sql`)
`ALTER TYPE auth_event_type ADD VALUE IF NOT EXISTS 'tenant_selected'` (outside the transaction — Postgres refuses a new enum label inside the transaction that added it) · `tenants.status_before_suspend tenant_status` · `refresh_tokens.mfa boolean NOT NULL DEFAULT false` · `fam_tenant_notes` (ENABLE + FORCE RLS, deny-all policy, `REVOKE ALL FROM flicks_app`, index on `(tenant_id, created_at DESC)`) · `coupon_redemptions`: the old one-coupon-per-company-ever constraint is dropped for a unique index on `(tenant_id, coupon_id)`. Idempotent; ends with a six-row OK check. `scripts/sql/relock-grants.sql` mirrors the revoke. Drizzle schema mirrors every column and index.

**Order:** run `apply-0070.sql` in Supabase → push `production` (API) → push `main` (web). The API reads `status_before_suspend` and `refresh_tokens.mfa` from its first request.

- **Full gate:** API typecheck · API build · Jest **1469 / 1469** (96 suites) · `lint:boundaries` 0 violations (368 modules) · web typecheck · web production build · `diagnose-rls.sh` `leak_with_bogus_context = 0`.
- **Live** (`verify-roundR-r2.mjs`, production web build + real API with `TOTP_SECRET` set + Postgres + s3-mock): **110 / 110**. Drives the real screens: enrolment through `/totp-setup`, the 403 before and the 200 after; a pre-release session (mfa=false on its refresh row) meets the step-up card on `/fam/overview`, a wrong code is refused in place, the right one opens the console in the same tab; the platform-only check from a customer Owner; search → person page → clear lockout → send link → sign out everywhere (his session cannot refresh); Settings → Suspend → the customer's tab answers `TENANT_SUSPENDED`, sees the suspended screen, switches to his other company; a person with only that company sees the screen and signs out; Reactivate restores *trialing*; Billing → extend an expired trial (writes 402 before, allowed after, "Trial · 14 days left" on `/auth/me`) → give 2 free months (coupon on the panel, 2 calendar months in the database, ~75 days left) → a paying workspace's button is disabled; Support → activity rows, filter, CSV download, note add / pin / delete, app role denied; Members → resend invite, sign out of one company (his other session still refreshes); Audit → From column, category and actor filters, CSV, `?category=` deep link. Screenshots in the session scratchpad (`shots-roundR-r2/`).
- **Adversarial review** (five lenses — auth / sessions, tenant isolation, billing math, web dead ends, regressions + migration — every finding challenged by two skeptics): **24 findings, 23 confirmed, all fixed before release.** The ones that mattered:
  - **(high) 2FA gate redirect loop.** An enrolled admin whose session predates the release (every existing session: `refresh_tokens.mfa` is false for old rows and rotation carries it) was sent to sign-in, which sends an authenticated person straight back. Fixed with an in-place **step-up**: `POST /auth/totp/step-up` verifies the authenticator for the signed-in admin and re-issues the session with the claim; the console shows a "Finish two-factor" card instead of redirecting. Also closes the old-web window: the first visit after deploy asks for the code once.
  - **(medium) `/auth/me` memberships carried no `tenantStatus`**, so the web's "never auto-switch into a suspended company / never offer one as a way out" filters were inert. Every seat now carries `tenantStatus` + `tenantLogoUrl`.
  - **(medium) Socket handshakes** accepted a TOTP challenge token as a session and admitted a suspended company for the life of its access token — all four gateways now apply the same two rules as the HTTP side (`gateways/socket-session.ts`).
  - **(medium) Public API keys** kept working for a suspended company — `flk_live_` keys now answer `403 TENANT_SUSPENDED`.
  - **(medium) Self-service "one coupon ever"** lost its database guard when 0070 relaxed the unique constraint for repeatable FAM grants — the redeem transaction now takes a per-company advisory lock and re-checks inside it (two racing redeems of different codes: exactly one wins, proved in the spec).
  - **(medium) Support's internal reason and staff id** were written into the customer-visible plan history — `trial.extended` and `coupon.redeemed` events now carry only what the customer may see; the reason stays on the platform audit log.
  - **(medium) Extend trial on a live Razorpay subscription** reported a success that changed nothing — now refused (the button is disabled, the API says why); a canceled one is still extendable and its `current_period_end` slides as before; a company with no subscription row gets one, as the tab promised.
  - **(medium) `403 TENANT_SUSPENDED` on switch-company** reloaded the tab and wiped the message — account routes are excluded from the reload.
  - **(low)** a support sign-in link shadowed the person's own emailed code (and a new code request killed the link) — link-only rows carry no code hash and are skipped by both paths; "sign out everywhere" also ends an impersonation the admin is running; the Owner's billing page shows the latest coupon; note actions refresh the audit views; fragment keys; the Drizzle index mirror; a month-end arithmetic bug in the spec itself.
  - Refuted / not acted on: the "old web against new API" window (the step-up handles it on the first visit).

## 5. Residuals / notes for the next round
- A session that is signed out by support (or by a suspension) keeps its **access token for up to 15 minutes**: tenant routes refuse a suspended company at once (the guard checks the company on every request), but "sign out everywhere" and "sign out of this company" only stop the *next* refresh. A per-request session check would cost a lookup per call; the dialogs say "within 15 minutes" rather than overclaim.
- The sign-in link, the suspend / reactivate mails and the coupon note go through the normal mailer; when it refuses an address the console reports the failure (the audit row records `sent: false`).
- Real-time fan-out is still in-process socket.io (single instance) — `seat.revoked` disconnects sockets on the instance that handles the request.
- Platform-admin two-factor is enforced only where `TOTP_SECRET` is configured (production). Local development stays code-only.
